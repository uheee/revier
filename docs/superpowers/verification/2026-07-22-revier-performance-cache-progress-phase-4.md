# Revier 性能缓存与进度反馈：阶段四验证记录

## 1. 本阶段成果

- 新增分支缓存恢复、缓存状态查询和上次选中文件持久化命令。
- 打开项目或切换分支时直接恢复该分支最近一次成功快照；无缓存时保持空工作台，不自动分析。
- 当前 HEAD 与缓存 HEAD 不一致时返回 `stale`，继续展示旧快照，由“重新分析项目”按钮显式刷新。
- 刷新成功后替换文件列表并选择首项；刷新失败或取消时保留刷新前任务与文件结果。
- `review_start_analysis` 增加 `operation_id`，后端通过 `review://operation-progress` 推送进度。
- 普通进度事件最多每 100 毫秒发送一次；阶段变化和终态立即发送。
- 新增底部操作状态栏，运行期间每 100 毫秒刷新本地耗时，完成后保留本次耗时。
- 每分支快照仅用一个可空文本字段保存上次选中文件；写入前验证文件属于当前快照。

## 2. 数据迁移

- schema 版本由 2 升至 3。
- `analysis_snapshots` 新增可空 `last_selected_path`。
- `1 -> 2 -> 3` 和 `2 -> 3` 均在事务中迁移。
- 迁移测试证明版本二的已有项目快照不会被删除或改写。

## 3. 自动化验证

执行命令：

```text
cargo test --workspace -j 1 --config 'profile.test.debug=0'
cargo clippy --workspace --all-targets -j 1 -- -D warnings
pnpm typecheck
pnpm test
pnpm lint
```

结果：

- Rust 全工作区测试全部通过；新增终态接收器释放测试后，`revier-tauri` 53 项测试通过。
- Rust Clippy 全目标零警告通过。
- TypeScript/Vue 类型检查通过。
- 前端 31 个测试文件、189 项测试全部通过。
- ESLint 通过。

## 4. 关键行为证据

- 缓存缺失恢复不会创建分析任务。
- 新服务实例可从 DuckDB 恢复完成任务、筛选、文件列表及上次选中文件。
- HEAD 新增提交后恢复结果为 `stale`，不会触发重新分析。
- 相同仓库的不同分支仍使用 `(repo_id, branch)` 唯一快照，互不覆盖。
- 普通同阶段事件在 100 毫秒窗口内被抑制，阶段变化立即发出。
- 终态生成后释放已注册事件接收器，避免长期持有应用句柄。
- 状态栏测试证明运行耗时持续增长，完成后显示固定的“本次耗时”。

## 5. 阶段边界

本阶段恢复的是项目快照和可浏览任务上下文。文件作者轨、块归因与提交下钻的 DuckDB 快速读取和刷新按钮属于阶段五、阶段六，本阶段未提前改变其缓存语义。
