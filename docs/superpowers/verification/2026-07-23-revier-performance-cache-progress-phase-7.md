# Revier 性能缓存与进度改造：阶段七验收记录

## 1. 本阶段范围

本阶段统一项目缓存恢复、项目分析、文件读取、Monaco 差异、文件归因、编码重载和提交下钻的前台操作状态，补齐持续耗时、确定进度、缓存状态与无障碍播报。性能矩阵和最终全量回归属于阶段八。

## 2. 操作状态模型

- `ReviewStore` 保存当前前台操作 ID、当前快照和最后终态快照。
- 新操作开始后，不同操作 ID 的迟到事件不得覆盖当前状态；同一操作到达终态后，不接受倒退到运行态的事件。
- 分支缓存恢复从请求发出起显示 `project-metadata`，而不是只在完成后瞬间写入结果。
- 项目列表和项目分支列表也在请求期间显示 `project-metadata`，失败时保留对应终态与耗时。
- 文件加载完成后切换为 `monaco-diff`；Monaco 产生有效变更块后切换为 `file-attribution`。
- 编码重载开始时使用 `encoding-reload`，随后沿同一操作 ID 进入 Monaco 与归因阶段。
- 后端文件操作注册可随阶段更新操作类型，使事件与前端当前阶段一致。
- 完成终态统一携带 `100%`；失败和取消不伪装为完成进度。

## 3. 状态栏与交互

- 全局操作状态栏始终保留，因此没有打开文件时仍能看到项目分析或缓存恢复状态。
- 编辑器内状态栏继续负责行列、编码、语言和“重新分析当前文件”，避免复制现有编辑器交互。
- 全局状态栏显示操作消息、分支、文件、提交短哈希、缓存状态、进度和耗时。
- 运行中显示“已用”，每 100 ms 刷新；终态显示“本次耗时”并保留结果。
- 只有已知总量、后端提供比例或完成终态才渲染原生 `progress`；未知总量仅显示操作和耗时。
- 窄宽度下优先保留操作对象与耗时，隐藏缓存标签和进度条图形。

## 4. 无障碍与限频

- 后端普通同阶段进度沿用最高 10 Hz，阶段变化立即发出。
- 视觉耗时最高 10 Hz 更新。
- `aria-live` 独立于视觉计时，仅包含操作消息、目标和进度；耗时刷新不会反复触发读屏。
- 原生进度元素带有“当前操作进度”标签；未知总量不提供错误的进度条语义。

## 5. 测试覆盖

- 连续耗时、终态耗时保留和完成进度。
- 未知总量不渲染进度条。
- 分支、文件、提交短哈希与缓存命中状态。
- 视觉耗时刷新不改变读屏播报内容。
- 缓存恢复运行态与终态、旧操作并发隔离。
- 文件打开、编码重载、Monaco Diff、文件归因和最后终态类型转换。
- 后端 Monaco／归因事件类型、连续耗时和完成比例。

## 6. 架构说明

原计划把全部信息扩展进 `EditorStatusBar`。现有阶段四和阶段五已经形成“全局操作栏 + 编辑器上下文栏”的职责划分：前者在无文件时也存在，后者拥有行列、编码、语言和文件刷新操作。本阶段保持该结构，只补齐两者合计需要承载的信息，避免在两个组件之间复制编辑器交互状态。

## 7. 阶段边界

阶段七只完成统一状态覆盖和可访问性。当前仓库性能矩阵、最终全工作区测试、README 与迁移汇总在阶段八执行，需在阶段七成果审核通过后开始。
