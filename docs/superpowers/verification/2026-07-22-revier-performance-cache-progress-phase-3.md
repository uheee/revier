# Revier 性能缓存与进度改造：阶段三验收记录

## 1. 验收范围

本阶段交付增量提交索引、范围文件差异性能优化、项目快照原子发布和后端项目分析进度。项目打开时恢复缓存、文件归因缓存命中和前端统一状态栏仍属于后续阶段。

## 2. 增量索引结果

- 每次构建只遍历一次目标分支可达集合，并与 DuckDB 已有提交哈希求差集。
- 只对缺失提交执行父差异计算；已索引提交不再执行 diff。
- 缺失提交、父关系、文件记录和运行记录在单个事务中写入。
- 写入失败或执行中取消会回滚提交、文件和运行记录。
- 多分支共享提交只保存一次。
- 所有本地分支引用通过一次多起点 rev-walk 计算，支持分支 force-move。
- 项目快照替换和不可达提交清理处于同一事务；新发布失败时旧快照保持可读。
- 清理会保留所有本地分支可达提交及当前快照引用链。

实际 diff 调用验证：首次索引后新增一个提交，第二次只调用一次提交 diff；不新增提交时 `indexedCommitCount` 为 0。

## 3. 文件差异与统计结果

- 新增不读取文件正文的范围树差异接口，直接返回 old/new Git blob ID。
- 树阶段只执行基于 blob ID 的精确重命名识别。
- “重命名并修改”通过已有提交索引的 rename 路径关系合并，不在筛选前读取正文。
- 作者、提交信息和 glob 筛选完成后，只对最终入选文件读取 blob 并计算行数。
- 旧 `range_file_changes()` 保留相似度重命名行为，现有调用兼容。
- 项目快照保存 blob ID，不保存源码正文。

## 4. 项目快照与进度

- `ReviewService` 先构造候选分析结果，完整成功后才发布分支快照。
- 分析失败或取消时继续保留上一个成功快照。
- 发布完成后内存任务结果与数据库快照来自同一候选结果。
- 快照完成时间和耗时在发布事务核心写入完成后采样。
- 后端任务进度覆盖：范围解析、仓库读取、缺失提交索引、索引写入、文件筛选、文件统计和缓存发布。
- 进度包含当前阶段、完成量、总量、比例和操作描述。
- 调试构建设置 `REVIER_TRACE_OPERATIONS=1` 时输出阶段累计耗时，不记录源码正文或筛选内容。

## 5. 本机性能样本

环境：Windows、debug 测试构建、单并发 Cargo、两至三个提交和一个最终文件的合成仓库。以下数据只作为本机回归基线，不作为生产绝对阈值。

独立索引命令：

- 首次索引：246 ms，写入 2 个提交。
- 新增一个提交后的增量索引：230 ms，只写入 1 个提交。

项目分析累计阶段时间：

| 阶段 | 首次分析 | 单提交增量刷新 |
| --- | ---: | ---: |
| 范围解析完成 | 73 ms | 6 ms |
| 缺失提交 diff 完成 | 224 ms | 130 ms |
| 索引写入完成 | 261 ms | 164 ms |
| 文件筛选开始 | 360 ms | 274 ms |
| 文件统计完成 | 365 ms | 279 ms |
| 缓存发布完成 | 471 ms | 401 ms |
| 快照记录耗时 | 464 ms | 391 ms |

快照耗时在事务提交前、核心写入和清理完成后采样，因此与外部进度终态相差约 7 至 10 ms。

## 6. 自动化验证

以下验证通过：

```powershell
cargo test --workspace -j 1 --config 'profile.test.debug=0'
cargo clippy --workspace --all-targets -j 1 --config 'profile.test.debug=0' -- -D warnings
pnpm typecheck
pnpm test
pnpm lint
```

覆盖场景包括：

- 无新增提交、单提交增量和多分支共享提交。
- force-move 后的本地可达集合与旧 HEAD 清理。
- 写入失败、执行中取消和发布清理失败的事务回滚。
- 精确重命名、重命名并修改、glob 旧路径和最终行数统计。
- 项目分析成功发布、失败保留和取消保留。
- 项目任务阶段、描述和比例更新。

Rust 全工作区测试、Clippy、TypeScript 类型检查、30 个前端测试文件中的 184 项测试及 ESLint 均通过。

## 7. 阶段边界

本阶段已经消除“每次项目分析清空并重算全部提交”和“筛选前为所有最终文件读取正文”的主要路径，并将成功项目结果持久化。下一阶段才会实现打开项目直接恢复分支快照、HEAD 过期判断和对应 Tauri 接口。
