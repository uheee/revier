# Revier 性能缓存与进度改造：阶段五验收记录

## 1. 本阶段范围

本阶段交付文件内容快速读取、文件作者轨持久化缓存、当前文件显式刷新和文件操作进度。提交下钻缓存读取仍属于阶段六，本阶段不提前实现。

## 2. 实现结果

### 2.1 文件内容快速路径

- 项目分析快照中的 `analysis_files` 已保存旧、新 Blob ID。
- 打开文件时按项目、分支和路径读取当前 `analysis_id` 下的文件记录，再直接按 Blob ID 读取 Git 对象。
- 文件打开不再重新执行范围树差异，也不再依赖内存任务中的 base/head 提交解析。
- Blob 不存在或对象类型错误时返回稳定的 `CACHE_INVALID`，不会把缺失内容伪装为空文件。

### 2.2 文件归因缓存

- Monaco 生成规范块签名后，普通打开以 `prefer-cache` 查询当前文件缓存。
- 缓存命中需同时满足：当前 `analysis_id`、分析算法版本、实际文本编码和规范块签名一致。
- 命中后批量读取关联提交元数据，并恢复作者、相关提交、触达范围、归因方式、置信度和警告标记。
- 未命中时只计算当前文件，成功后通过单事务原子替换文件分析。
- 数据库只保存块几何、紧凑枚举/标志、提交哈希及范围，不保存源码正文或重复提交元数据。

### 2.3 当前文件刷新

- 编辑器状态栏新增“重新分析当前文件”按钮。
- 刷新请求使用 `cache_mode=refresh`，跳过现有文件归因缓存并重新计算当前文件。
- 项目缓存过期、文件不可预览、二进制文件或刷新进行中时按钮禁用。
- 新结果完整归因并发布成功后，界面才切换到新结果，同时关闭旧提交下钻；数据库替换会删除该文件旧下钻缓存。
- 文件读取、归因失败或前端取消时，继续展示原文件、作者轨、选中块和提交下钻；旧数据库缓存不被删除。

### 2.4 状态栏进度与耗时

- 文件打开和刷新共用一个 `operation_id`。
- 后端依次报告“读取文件内容”“计算差异”“归因候选”“完成/失败”。
- 前端 Monaco 计算阶段与后端事件合并到同一操作，底部状态栏每 100 ms 刷新实时耗时。
- 完成后显示缓存状态和本次总耗时；缓存命中显示“已从缓存加载”。
- 文件操作注册有一小时过期清理和 128 项上限，异常终止不会无限积累事件句柄。

## 3. 一致性与空间约束

- 每个项目的不同分支仍各保留一份最近成功项目快照。
- 每个项目快照中的每个文件只保留一份当前文件分析；新编码或显式刷新成功后原子替换。
- 文件缓存从属于不可变 `analysis_id`，不会把新 HEAD 的单文件结果写入过期项目快照。
- 关联提交只保存哈希引用，显示元数据从已有提交索引批量恢复。
- 失败的文件缓存事务会回滚并保留旧文件分析；成功刷新会清除该文件下的旧提交下钻。

## 4. 测试覆盖

新增或扩展的关键测试包括：

- 直接按缓存 Blob ID 读取内容，并验证范围提交被破坏后仍可打开文件。
- Blob 丢失返回稳定缓存失效错误。
- 首次文件归因写入缓存、同签名再次打开命中缓存。
- 显式刷新返回 `refresh`，刷新后普通打开再次命中。
- 文件缓存原子替换、失败回滚和刷新清除下钻。
- 文件操作阶段使用同一操作 ID，耗时单调递增。
- 刷新读取或归因失败时保留旧文件、作者轨和提交下钻。
- 刷新成功后才切换文件结果并关闭旧下钻。
- 当前文件刷新按钮事件、禁用态和刷新中文案。

## 5. 性能记录

在本阶段线性 Git 夹具与未优化测试构建中：

| 场景 | 本次耗时 |
| --- | ---: |
| 首次文件归因并写入缓存 | 255 ms |
| 同编码、同规范块签名热缓存恢复 | 104 ms |

该数据用于验证冷热路径确实分流，不代表大型真实仓库的绝对耗时。热缓存路径不执行 patch inference、blame 或删除追踪，仅读取 Blob、文件缓存和批量提交元数据。

## 6. 验证命令

- `pnpm lint`：类型检查与 ESLint 通过。
- `pnpm generate:bindings:check`：提交后复验 Rust/TypeScript bindings 无差异。
- `git diff --check`：通过。

## 7. 阶段边界

当前普通文件打开和作者轨已经支持持久化热缓存，当前文件可以独立刷新。点击具体提交时仍会按现有逻辑重新执行可达性、历史路径和提交 Diff 计算；这部分将在阶段六接入 `commit_overlays` 缓存读取和发布。
