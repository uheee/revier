# Revier Review 工作台交互改进设计

> 状态：已确认。本文记录本轮针对项目打开、筛选控件、完整文件对比、三栏宽度调整、提交下钻的改进设计。实现前应先确认本文范围，再拆分实施计划。

## 背景

当前 MVP 已经具备项目管理、筛选分析、文件列表、变更块展示和右侧详情，但还有几处会直接影响日常 review 效率：

- 项目路径只能手写，新增项目缺少目录选择、重复仓库校验和非 Git 仓库校验。
- 筛选条件大多是文本输入，分支、作者、时间范围没有使用符合语义的控件。
- 中间栏目前只按变更块展示 diff，不能像常规代码 review 一样同时看到旧版和新版完整文件。
- 三栏宽度固定，无法按仓库路径、diff 宽度、详情内容调整工作区。
- 右侧相关提交只能阅读，不能点击进入单个提交的差异详情。

本轮目标是在保持现有 Vue 3 + TypeScript + Electron + Element Plus 技术栈的前提下，把这些交互补齐为可用于真实代码 review 的工作台体验。

## 目标

本轮完成后应满足：

- 新增项目时可以点击路径输入区或按钮打开系统目录选择对话框。
- 选择目录后自动填充仓库路径，并将项目名称设置为目录名。
- 重复添加同一仓库时显示明确错误。
- 添加非 Git 仓库时显示明确错误。
- Review 筛选区使用分支下拉、作者多选、日期范围选择器，而不是要求用户手写所有条件。
- 中间栏默认展示完整旧文件与完整新文件的 side-by-side 对比，所有变更行在完整上下文中高亮。
- 左、中、右三栏宽度可以通过拖拽调整，并在当前设备上持久化。
- 右侧提交列表可以点击下钻，点击后中间栏展示该提交对当前文件的变更内容。
- 下钻区域左上角有返回按钮，可关闭下钻并回到当前筛选范围的叠加 diff。
- 下钻状态下再次点击另一个提交时，中间栏刷新为新提交的变更详情。
- 下钻打开和切换动画使用由右向左移动覆盖的方式。

## 非目标

本轮不做以下内容：

- 不实现远程仓库克隆、认证或 Git 托管平台集成。
- 不做跨项目搜索或批量导入仓库。
- 不做完整 SQLite 索引。
- 不做复杂 merge commit 多父对比。提交下钻沿用 MVP 口径：merge commit 默认按第一父提交计算。
- 不引入新的大型 UI 框架。
- 不重做整体视觉风格，继续遵循已确认的 Revier MVP 视觉方案。

## 推荐方案

采用“主进程补齐仓库能力 + 渲染层结构化控件 + 中间栏可切换视图”的方案。

核心思路：

- 项目新增流程通过 Electron 主进程调用系统目录选择对话框，并在主进程统一做路径规范化、Git 仓库校验和重复仓库校验。
- Review 筛选区在打开项目后加载分支和作者候选项。分支使用单选下拉，作者使用多选，时间使用日期时间范围选择器，提交信息和文件 glob 保留文本输入。
- 文件 overlay 数据扩展为“完整文件行 + 变更块元数据”。渲染层不再只遍历变更块，而是渲染完整 side-by-side 行序列，并把变更块映射到对应行上。
- 三栏通过两个拖拽分隔条控制宽度，宽度值保存在 `localStorage`，保持桌面工具的可调性。
- 提交下钻作为中间栏的覆盖层视图。默认层是筛选范围 overlay；下钻层是单提交 diff。右侧提交列表负责触发下钻，返回按钮负责关闭下钻。

选择该方案的原因：

- 改动边界清晰，不需要推翻当前 IPC、Pinia 和组件结构。
- 项目选择、仓库校验和 Git 元数据仍在主进程完成，符合 Electron 安全边界。
- 完整文件 diff 和提交下钻共享中间栏结构，避免重复实现两套 diff UI。
- 三栏拖拽只影响布局状态，不影响分析数据。

## 项目打开与新增项目

### 交互要求

新增项目表单中的“仓库路径”区域应支持两种方式：

- 点击路径输入框右侧的文件夹按钮，打开系统目录选择对话框。
- 用户仍可手动粘贴路径。

选择目录后：

- `repoPath` 自动填入选择的目录路径。
- `name` 自动设置为目录名称。例如选择 `E:\Projects\revier` 后，项目名称为 `revier`。
- 用户仍可在提交前手动修改项目名称。

提交新增项目时：

- 如果目录不是 Git 仓库，表单上方或路径字段下方显示错误：`请选择一个 Git 仓库目录`。
- 如果同一仓库已经存在，显示错误：`该仓库已在项目列表中`。
- 重复判断应基于规范化后的仓库根目录，而不是用户输入字符串。`E:\Projects\revier`、`E:/Projects/revier/`、仓库子目录都应归一到同一个 Git root 后比较。
- 添加成功后清空表单，并刷新项目列表。

### 主进程能力

需要在 projects IPC 中新增目录选择能力：

- 渲染层请求打开目录选择对话框。
- 主进程调用 Electron `dialog.showOpenDialog`，限制为目录选择。
- 用户取消时返回 `undefined`，不报错。
- 用户选择目录时返回选择路径，以及根据路径推导出的目录名。

需要强化仓库校验能力：

- `validateRepository(repoPath)` 应返回规范化仓库根路径。
- 非 Git 仓库返回可恢复错误。
- Git 仓库子目录应解析到仓库根目录。
- 项目存储新增项目前检查是否已有相同规范化根路径。

## 筛选控件

### 分支

分支字段从普通文本框改为下拉选择：

- 数据来自项目已有的 `projects.listBranches(projectId)` 能力。
- 默认选中项目偏好的默认分支；没有偏好时选中当前分支；没有当前分支时使用 `HEAD`。
- 下拉项显示分支名，当前分支可附带轻量标记。
- 分支列表加载失败时显示错误提示，并允许用户保留 `HEAD` 作为兜底值。

### 作者

作者字段从单行文本改为多选下拉：

- 数据来自当前项目 Git 提交作者列表。
- 作者项展示 `姓名 <邮箱>`；没有邮箱时只展示姓名。
- 支持搜索过滤候选作者。
- 提交给主进程时使用作者列表数组，而不是拼接文本。
- 空数组表示不过滤作者。

作者候选项的推荐来源：

- 打开工作台后，按当前分支读取近期提交作者作为初始候选。
- 当分支或时间范围变化后，允许刷新作者候选，使候选项与当前分析范围一致。
- 为避免打开大型仓库时阻塞 UI，作者候选可按需加载，并显示加载状态。

### 时间范围

开始时间和结束时间从两个文本框改为日期时间范围选择器：

- 使用 Element Plus 日期时间范围控件。
- 默认范围沿用项目偏好或 MVP 默认最近 30 天。
- 可清空。清空后由主进程按既有默认规则解析。
- 提交给主进程时转换为 ISO 字符串。
- 结束时间不得早于开始时间；若用户选择非法范围，阻止分析并显示字段级错误。

### 提交信息和文件规则

提交信息仍保留文本输入：

- 支持普通关键词。
- 为空表示不过滤提交信息。

文件规则仍保留多行文本：

- 继续支持 glob include/exclude。
- 保留 `!pattern` 排除语义。
- 规则 chip 不属于本轮要求。

### 类型调整

`ReviewFilters` 需要表达结构化筛选：

- `branch: string`
- `startAt?: string`
- `endAt?: string`
- `authors: AuthorSummary[]` 或 `authorEmails: string[]`
- `messageQuery?: string`
- `globRules: string[]`

推荐使用稳定的作者 key 作为筛选值：

- 有邮箱时用邮箱。
- 无邮箱时用姓名。

主进程匹配作者时应同时兼容姓名和邮箱，避免历史提交缺少邮箱时无法筛选。

## 完整文件 side-by-side 对比

### 显示规则

中间栏默认显示当前文件在筛选范围内的完整旧文件和完整新文件：

- 左侧为起始点文件内容。
- 右侧为结束点文件内容。
- 两侧都显示完整文件行，而不是只显示变更块。
- 变更行在完整上下文中高亮。
- 未变更行使用普通背景。
- 新增行右侧高亮，左侧显示空占位。
- 删除行左侧高亮，右侧显示空占位。
- 修改行两侧都高亮，并保留词级高亮。
- 每个变更块在对应行旁显示作者标签。
- 点击高亮变更块时选中该块，并同步右侧详情。

### 数据结构

现有 `FileOverlay.blocks[].rows` 只能支撑按块渲染。需要增加完整文件行序列，例如：

- `FileOverlay.rows: SideBySideDiffRow[]`
- `DiffBlock.rowIndexes` 或 `DiffBlock.rowStartIndex / rowEndIndex`

渲染层使用 `FileOverlay.rows` 生成完整文件表格，再通过块索引决定：

- 哪些行属于哪个变更块。
- 哪些行可点击。
- 当前选中块的高亮范围。
- 作者标签显示在哪一段变更区域旁。

### 大文件行为

完整文件渲染会比只渲染变更块更重。本轮要求：

- 保留大文件软限制。
- 超过限制时显示确认加载提示。
- 已加载后中间栏滚动性能不能因为一次性 DOM 过多明显卡顿。
- 如果实现阶段需要虚拟滚动，必须保持左右行号、代码列、块点击区域对齐。

## 三栏宽度调整

### 布局规则

Review 工作台仍保持左、中、右三栏：

- 左栏：筛选区和文件列表。
- 中栏：完整文件 diff 或提交下钻 diff。
- 右栏：变更块详情和提交列表。

新增两个拖拽分隔条：

- 左栏和中栏之间一个。
- 中栏和右栏之间一个。

拖拽时：

- 实时调整相邻栏宽。
- 左栏最小宽度 `260px`，最大宽度 `460px`。
- 右栏最小宽度 `280px`，最大宽度 `520px`。
- 中栏最小宽度 `520px`。
- 当窗口过窄导致无法满足最小宽度时，中栏优先保留可读宽度，左右栏按最小宽度收缩。

### 持久化

宽度设置保存在 `localStorage`：

- key 建议为 `revier.reviewLayout.v1`。
- 保存左栏宽度和右栏宽度。
- 重新打开应用或切换项目后沿用上次宽度。
- 如果保存值超出当前窗口可用范围，应按最小/最大值修正。

## 提交下钻

### 入口

右侧详情面板中的相关提交列表变为可点击列表：

- 点击某个提交，进入提交下钻状态。
- 被点击提交行显示选中状态。
- 若该提交命中当前筛选，保留 `命中筛选` 标签。
- 下钻请求基于当前任务、当前文件、当前变更块和提交 hash。

### 中间栏下钻视图

进入下钻后，中间栏显示单提交对当前文件的变更：

- 视图左上角显示返回按钮。
- 标题显示提交短 hash、提交标题和作者。
- 内容使用与默认 diff 相同的 side-by-side 表格组件。
- 左侧为该提交父提交中的文件内容。
- 右侧为该提交后的文件内容。
- 对 merge commit 默认使用第一父提交。
- 只展示当前提交对当前文件的变更上下文。若要复用完整文件表格，也必须能清晰标记该提交的变更行。

返回按钮行为：

- 点击后关闭下钻层。
- 中间栏恢复当前筛选范围的叠加 diff。
- 右侧详情仍保持当前变更块选中状态。

切换提交行为：

- 下钻状态下点击右侧另一个提交，不退出下钻。
- 中间栏直接刷新为新提交的变更内容。
- 右侧提交选中状态切换到新提交。

### 动画

提交下钻打开和切换时使用由右向左移动覆盖：

- 新的下钻层初始位于中间栏右侧。
- 动画过程中向左移动并覆盖当前中间栏内容。
- 动画时长建议 `180ms` 到 `240ms`。
- 使用 `transform` 和 `opacity`，避免触发布局抖动。
- 如果用户开启系统减少动态效果设置，应关闭位移动画，直接切换。

关闭下钻时：

- 返回到默认 overlay，不播放新的覆盖动画，避免造成“又进入一层”的错觉。
- 可使用短淡出或直接关闭。

### 主进程能力

需要新增提交下钻数据接口，例如：

- `review.getCommitOverlay({ taskId, filePath, commitHash })`

返回值建议与 `FileOverlay` 结构保持兼容，额外包含：

- `commit: RelatedCommit`
- `parentHash`
- `mode: 'commit'`

数据来源：

- 使用 `git show` 或读取父提交/当前提交文件内容计算单提交 diff。
- 若提交未触碰当前文件，返回可恢复错误：`该提交未修改当前文件`。
- rename 文件应优先使用当前 `ChangedFile.path` 与 `oldPath` 两个路径尝试读取。

## 错误处理

项目添加：

- 用户取消目录选择：不显示错误。
- 目录不存在：显示 `目录不存在或无法访问`。
- 非 Git 仓库：显示 `请选择一个 Git 仓库目录`。
- 重复仓库：显示 `该仓库已在项目列表中`。
- Git 命令失败：显示可恢复错误，并保留用户输入。

筛选：

- 分支列表加载失败：显示错误，并保留 `HEAD`。
- 作者候选加载失败：显示错误，但不阻止用户按其他条件分析。
- 日期范围非法：阻止分析，并显示字段级错误。

下钻：

- 提交 diff 加载中时，中间栏显示加载状态。
- 下钻加载失败时，下钻层显示错误和返回按钮，不清空默认 overlay。
- 用户切换文件或重新分析时自动关闭下钻状态。

## 验收标准

项目新增：

- 点击路径输入区的文件夹按钮可以打开目录选择对话框。
- 选择 `E:\Projects\revier` 后，路径填入该目录，项目名自动填为 `revier`。
- 重复添加同一 Git root 时显示重复错误，不新增项目记录。
- 添加非 Git 目录时显示非 Git 仓库错误，不新增项目记录。

筛选：

- 分支字段是下拉选择，并显示当前仓库分支。
- 作者字段是可搜索多选，并能选择多个作者。
- 时间字段是日期时间范围选择器，输出 ISO 时间。
- 非法时间范围不能启动分析。
- 提交信息和 glob 规则继续可用。

完整文件 diff：

- 打开文件后，中间栏左右两侧显示完整旧文件和完整新文件。
- 未变更行也可见。
- 新增、删除、修改行在完整上下文中高亮。
- 点击任意高亮块后，右侧详情切换到对应块。

三栏宽度：

- 左右分隔条可拖拽。
- 刷新窗口后宽度设置仍保留。
- 窗口缩小时不出现三栏互相覆盖或文本严重溢出。

提交下钻：

- 点击右侧相关提交后，中间栏出现单提交 diff 下钻层。
- 下钻层左上角有返回按钮。
- 返回后恢复筛选范围叠加 diff。
- 下钻状态下点击另一个提交，中间栏刷新为新提交 diff。
- 打开和切换下钻时动画方向为由右向左覆盖。

## 测试建议

单元测试：

- 项目路径规范化和重复仓库判断。
- 非 Git 仓库校验错误。
- 作者筛选结构化匹配姓名和邮箱。
- `FileOverlay.rows` 与 `DiffBlock` 行索引映射。
- 单提交 overlay 在普通提交、rename、未触碰文件时的返回结果。

组件测试：

- `ProjectEditor` 选择目录后自动填入路径和名称。
- `FilterPanel` 分支下拉、作者多选、日期范围输出正确 filters。
- `DiffViewer` 能渲染完整文件行，并对变更行触发块选择事件。
- `BlockDetailPanel` 点击提交后触发下钻事件。
- 三栏拖拽保存和恢复宽度。

端到端测试：

- 从项目页选择当前仓库目录并成功添加项目。
- 重复添加当前仓库时显示错误。
- 打开项目后使用分支下拉、作者多选、日期范围运行分析。
- 打开一个文件后看到完整 side-by-side diff。
- 点击变更块，再点击右侧提交，进入下钻并返回。

## 实施边界

本 spec 只定义本轮交互改进。实施计划应按以下顺序拆分：

1. 项目选择、路径规范化、重复/非 Git 校验。
2. 筛选元数据接口和结构化筛选控件。
3. 完整文件 overlay 数据结构和 diff 渲染。
4. 三栏拖拽布局和持久化。
5. 右侧提交下钻和中间栏覆盖视图。

每一步都应有可独立验证的测试和提交。
